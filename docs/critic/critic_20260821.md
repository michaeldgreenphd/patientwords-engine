## HIGH · Finding 1 — the two served Neuronpedia host ids separated on 2026-07-31, and the daily lens sentinel could not see it

**What is true.** `docs/routine_standing_prompt.md` §3d records a "known alias": the
`gemma-2-2b` and `gemma-2-2b-it` ids "currently return byte-identical readouts … the day
the -it responses diverge is the day Neuronpedia separates the hosts, and the sentinel
catches it."

The sentinel did *capture* the separation. Nothing ever *computed* it. Recomputing all 28
dated lens readouts on disk:

| host id | day-over-day steps | target-rank hits before → after |
|---|---|---|
| `gemma-2-2b` | **2026-07-31**, 2026-08-14 | 71 → 51, then 51 → 50 |
| `gemma-2-2b-it` | 2026-08-14 | 71 → 76 |

Cross-host agreement by day: identical on 2026-07-14 … 2026-07-30 (10 measured days),
**DIVERGENT on every one of the 18 measured days since 2026-07-31**.

Sentinel request parameters are byte-identical across the whole series
(`lens_type` JACOBIAN_LENS, `top_n` 8, `endpoint` /api/lens/prompt, same 3 frozen pairs),
so the step is host-side, not ours.

**Why 21 days passed.** Every cycle's reading was individually true and collectively
blind: each compared each host id **only to the immediately preceding sentinel day**, and
phrased the verdict as "byte-identical to <yesterday> for both served host ids". A step
that lands once and then holds is invisible to that comparison from the following day
onward. §3d's own instruction — "compare formation depths against the day-1 baseline
(2026-07-14)" — was never mechanized, so it was never done.

**Check written (feed-forward).** `scripts/lens_sentinel_check.py` (new, $0, offline,
read-only) compares every dated readout against both the previous day *and* the day-1
baseline per host id, and reports cross-host agreement per day. Exit 1 = a step landed on
the latest day (a DRIFT headline the brief must carry); exit 0 = no new step, with any
historical steps and the divergence window still printed so they cannot silently age out.
Regression coverage in `tests/test_lens_sentinel_check.py` (5 tests, passing), including
`test_historical_step_survives_a_quiet_latest_day`, which encodes this exact blind spot.

Current output:

```

gemma-2-2b@20260731, gemma-2-2b@20260814, gemma-2-2b-it@20260814;
served host ids DIVERGE since 20260731 (18/28 days)
```

**Exposure.** Committed j-lens part files by host-state era (excluding sentinel dirs):
45 part files across 23 lens dirs pulled **before** 2026-07-31; 61 files across 26 dirs in
2026-07-31 … 2026-08-13; 2 files after 2026-08-14. So `data/jlens_depth.json`,
`jlens_insights.json`, `jspace.json`, the transport/loglens payloads, and the txcorpus
lens-recovery line are each built from readouts spanning up to three distinct host states.
That is a provenance fact the methods page does not currently state.

**Not done here, needs the owner:** whether to annotate the lens payloads with the
host-state era, re-pull the census batch under the current host, or state the mixture in
the methods repeatability note. All three are text or re-measurement decisions outside a
data-mandate cycle.

## HIGH · Finding 2 — the published instruction-tuning comparison is 72 % daily-sentinel replicates, and the site prose it feeds is now false

Found while checking whether Finding 1 had reached any published number. It had.

`scripts/jlens_insights.py:82` globs `*__jlens_*/jlens_summary.part_*.json` and excludes
`txcorpus_*`, `*_txopus`, `*_txplacebo`, `*__context` — but **not** `drift_sentinel_*`.
Each dated sentinel directory is therefore a distinct `dataset` key contributing its 3
pairs to the census, once per sentinel day, for both host ids.

Recomputed from the payload published this cycle
(`../patientwords/data/jlens_insights.json`):

- `instruction_tuning.n_paired` = **75**. Distinct `(index, base, it)` tuples = **25**.
  Index 2 appears 27 times, index 3 appears 27 times — the sentinel pairs, once per day.
  The genuine corpus is 21 census-batch phrases (indices 5–46, from
  `pairs_20260711T051145Z`, the only non-sentinel `__jlens_gemma-2-2b-it` dir on the
  branch, pulled 2026-07-11) plus 2 distinct sentinel phrases = **23 distinct phrases**.
- The published medians are driven by those replicates: `base_median` median 17,
  `it_median` median 8.
- **26 of the 75 rows are NOT identical** across the two ids, spanning 4 distinct phrase
  indices (2, 32, 35, 45).
- The replication also carries Finding 1's steps as a visible seam: index 2 appears as
  `(2, 8, 8) ×10` and `(2, 17, 8) ×17` — the base host's reading of one frozen phrase
  changing mid-series — and index 3 as `(3, 7, 7) ×21` and `(3, 7, 6) ×6`. That is
  independent corroboration of the 07-31 and 08-14 steps from a different artifact.

**The site prose contradicts its own payload.** `patientwords/technical/index.html`:

- L1354: `'… · every pair identical, so the two rows mirror each other exactly · not yet a tuning comparison'`
- L1356: `'The '+it.n_paired+' phrases read under both the gemma-2-2b and gemma-2-2b-it ids return identical lens readouts on every pair, so this is reported as one model — not a tuning comparison — until Neuronpedia confirms the two ids serve separate hosts.'`
- L523 (figure `aria-label`): `'… The readouts are identical on every pair.'`

All three assert identity that 26/75 published rows contradict, and rest on an alias the
sentinel data has contradicted since 2026-07-31. The sentence also interpolates
`it.n_paired` — so the page currently tells readers "75 phrases" when 23 distinct phrases
were measured.

**Nothing was changed here.** Site text is owner-only, and hand-patching an exported
payload is out of bounds. The fix is a one-line-class change to the collector's exclusion
list plus a republish, and then a prose rewrite the owner or orchestrator owns. Both are
in `decisions_pending` as `JLENS-SENTINEL-CONTAMINATION-20260821`.

**Secondary blast radius.** The same un-excluded sentinel rows sit in the base-model
formation census: 81 of 2,214 `points` rows (3.7 %) come from 27 sentinel datasets — 3
distinct phrases replicated 27×, growing by 3 rows every day the sentinel fires. It moves
the published census medians far less than it moves the tuning block, but it is the same
defect and the same fix.
